# 经济与建造模型：从"读账本"到"算最佳 BO"

目标：能回答"这套打法什么时候出门最好"、"这套 BO 的上限在哪"、"大招的最佳时间点"。

---

## 0. 关键发现：replay 本身就是一本账

`replay.tracker.events` 里的 `SPlayerStatsEvent` 有 39 个字段，其中这几个是**累计值**：

| 字段 | 含义 |
|---|---|
| `m_scoreValueMineralsCurrent` / `VespeneCurrent` | 手上剩的资源（存款） |
| `m_scoreValue{Minerals,Vespene}UsedCurrent{Army,Economy,Technology}` | 当前存活单位已花掉的资源，按用途分类 |
| `m_scoreValue{...}UsedInProgress{...}` | 正在建造/生产中的已花资源 |
| `m_scoreValue{...}Lost{...}` | 已经损失的资源 |
| `m_scoreValue{Minerals,Vespene}CollectionRate` | 收入速率（每分钟） |
| `m_scoreValueWorkersActiveCount` | 活跃农民数 |
| `m_scoreValueFoodUsed` / `FoodMade` | 人口（÷4096 得人口） |

于是**累计收入不用猜，直接算**：

```
collected(t) = bank(t) + Σ used_current(t) + Σ used_in_progress(t) + Σ lost(t)
```

验证（Rorschach LE，18:10，人族一方）：

- 账本算出总收入：矿物 17765 / 气 3654
- 把 730 个单位按 `units.UNIT_COST` 求和：矿物 17075（**96%**）/ 气 3075
- 差额主要来自**升级**（升级造价表还没建），以及极少数取消/回收

结论：只要补上升级造价，账本能闭合到 1~2%。**这意味着模型可以被逐秒验证**，
而不是"感觉差不多"。

## 1. 三层模型

### A. 收入模型

```
mineral_rate  = f(矿上农民数, 基地数, 矿骡, 是否有超频)
vespene_rate  = g(气矿数, 气上农民数)
```

不建议手填常数，直接拿语料拟合。实测（econ.py，90 局抽样）得到三个**必须分开**的数：

| 数 | 值 | 怎么来的 | 用在哪 |
|---|---|---|---|
| 理论上限 | **45.0 矿/分钟/农民** | 干净窗口的 p90 收敛（不再上升） | 仿真器算最优 BO |
| 实战有效值 | **25.1 矿/分钟/农民** | 账本增量拟合，R²=0.80 | 复盘预测、对账 |
| 游戏自报速率 | 约 48 | `m_scoreValueMineralsCollectionRate` | **不能直接积分**，比账本高 1.45x |

实战效率 = 有效值 / 理论上限：本机我的局 **52%**，职业局 **76%**（同一条测量规则）。

气体没有这层折损：3 农民满采 = **120 气/分钟/气矿**，实测 p50/p90 全部顶在 120。

要注意的是**饱和**：每片矿 2 个农民二点一采，16 个农民到顶；第 17~24 个农民几乎没有产出。
所以收入是 `min(农民数, 2×矿点)` 的分段线性，不是纯线性。

### B. 支出模型

建造事件（`SUnitInitEvent` / `SUnitBornEvent`）+ 造价表 → 现金流：

- **开工即扣钱**（建筑和单位都是）
- **完成才占人口**（虫族是卵→幼虫的离散模型）
- 升级、科技建筑单独一支

有了 A 和 B，就能写出余额方程：

```
bank(t+dt) = bank(t) + income(dt) - spend(dt)
```

这条方程可以和 replay 里真实的 `bank(t)` 逐点对账——**误差超过 5% 就说明模型错了**。

### C. 产能模型

钱通常不是瓶颈，**产能才是**：

- 兵营/重工/星港：每栋每分钟能出几个兵（挂反应堆 ×2，挂科技实验室换成科技）
- 星灵：折跃门冷却、超频
- 虫族：虫卵（每基地每 11 秒 1 个）+ 幼虫上限

例：2 兵营挂反应堆 = 每分钟 4 个枪兵位；想出 16 枪兵 + 4 医疗船，
瓶颈往往在星港的反应堆而不是矿。

## 2. 仿真器（离散事件）

状态：

```
(t, 矿, 气, 人口上限, 人口占用, 建筑列表(类型, 完成时间, 队列), 农民分配, 已研究科技)
```

推进方式：只在"事件时刻"推进（完成、到钱、到人口），不按帧。
一局 10 分钟的模拟应该是毫秒级，这样才能放进搜索循环。

**校准方法**：拿 replay 里真实的建造序列当输入跑一遍模拟，
对比"农民数 / 人口 / 军队价值"三条曲线与真实值的偏差。
偏差 < 5% 才算模型可用。

## 3. 优化：找最佳 BO

决策序列 = `[(时刻, 动作)]`，动作是有限模板：

- 补农民到 N（然后停止）
- 下第 k 个基地 / 兵营 / 气矿
- 挂反应堆 / 科技实验室
- 研究某科技
- 出某兵种队列

搜索：**beam search + 支配剪枝**。同一时刻，若状态 A 的资源、人口上限、产能、科技
全部不劣于 B，则 B 可以丢掉。beam 宽度 200~500 就能覆盖常见打法。

目标函数分两种：

1. **极限 timing**：`max army_value(T)`，或 `min T s.t. army_value(T) ≥ V`
2. **大招收益**：`max [我方兵力(T) - 对手防御(T)]`，这是下面要说的

## 4. 大招时机 = 两条曲线的交点

这是最值钱的部分，而且**不需要仿真器也能先做**。

- **我方曲线**：给定 BO，兵力/军队价值随时间（仿真或实测）
- **对手曲线**：从 replay 库里统计"同一对位、同一时间点的对手军队价值分布"

本机实测（TvZ，军队价值 = 兵种矿+气造价之和）：

| 时间 | 我的对局（对手中位） | Maru 的对局（对手中位） |
|---|---|---|
| 4:00 | 325 | 375 |
| 5:00 | 438 | 538 |
| 6:00 | 675 | 938 |
| 7:00 | 938 | 1488 |
| 8:00 | 1250 | 2038 |

用法：如果一套 2 基地打法在 6:00 能攒到 500 兵力，而对手这个时间点中位是 675，
那 6:00 出门就是亏的；同一套打法拖到 7:00 有 900，对手 938，仍然不占优——
**说明这套打法本身需要改**（要么更早、要么更高产能）。

把"你的曲线 - 他的曲线"画出来，**峰值区间就是这套打法的最佳出门时间**。

注意：军队价值不等于战斗力（人族小规模更强、地形、微操），所以这个量要把
"价值差"换算成"胜率"还需要一个校正系数，最好用你自己的对局拟合。

## 5. 容易漏掉的项

1. **移动时间**：到达时刻 ≠ 出发时刻。地图对角 ~45 秒（地面），这段要算进去
2. **视野**：对手什么时候发现你？可以直接接 `fog` 模块——"他看不见你的时间窗"
3. **人口卡顿**：补人口的时间点错了，会白丢 20~30 秒产能
4. **对手模型**：最优 BO 只对某一类对手最优。要按对手风格分组（狗毒爆 rush / 三基地经济）
5. **采样噪声**：`SPlayerStatsEvent` 约 10 秒一个点，做逐秒结论要插值

---

## 6. 建议的落地顺序

| 步骤 | 模块 | 产出 | 依赖 |
|---|---|---|---|
| 1 | `econ.py` | 账本解析 + 收入拟合 + 对账报告 | 无（数据已够） |
| 2 | `sim.py` | 离散事件模拟器，用 replay 校准 | 1 |
| 3 | `timing.py` | 对手防御曲线 + 交叉点分析 | 1（不必等 2） |
| 4 | `optimize.py` | beam search 找 BO | 2 |

第 1 和第 3 步加起来一天能出结果，而且**第 3 步已经能直接回答"什么时候打"**，
不用等完整仿真器。
